> 版本：v1.0（2026-09-23）　线上后端：https://zzy-ny73.onrender.com　前端：Vercel（GitHub 仓库 zhangjunyong123456/zzy，main 分支自动部署）

## 一、项目简介与产品定位

**UniGrow Agent** 是一个面向大学生「全生命周期」的 **多智能体（Multi-Agent）AI 成长平台**。用户在一个对话入口里说一句话，主 Agent 自动识别意图，调度 **学习、科研、竞赛、求职、校园** 五位垂直 Agent 并行工作，最终汇总成一份可执行的成长行动建议。

### 产品定位

- **一句话定位**：一颗会成长的 AI，陪你走完大学的每一段路。
- **目标用户**：在校大学生（从大一适应期到毕业求职期），以及需要学业/竞赛/求职规划辅助的研究生低年级。
- **核心差异**：不是单聊天机器人，而是「**路由 → 并行 → 汇总**」的多智能体协作架构；结合个人画像、长期记忆、知识库（RAG）三层上下文，做到「越用越懂你」。

### 功能全景

| 模块 | 说明 |
|---|---|
| 多智能体对话 | 主 Agent 意图路由，5 位专业 Agent 并行流式生成，主 Agent 二次汇总 |
| 知识库（RAG） | 上传课程资料 / 科研论文 / 简历 PDF，自动分块向量化，对话中检索增强 |
| 对话附件 | 图片（视觉模型识图）、PDF、PPT、Word 等随问随传 |
| 记忆系统 | 点选重要对话保存为长期记忆，后续对话自动注入【历史记忆】 |
| 个人画像 | 年级 / 专业 / 兴趣 / 经历 / 目标，自动融入每次回答 |
| 每日免费额度 | 未自带 Key 的用户每日可用服务器 Key 跑真 AI 若干次，用尽降级演示模式 |
| BYOK 自带 Key | 用户可配置 DeepSeek / 硅基流动 / 智谱 Key（仅存本地浏览器），对话直连模型厂商 |
| 数据统计 | 会话 / 提问 / 回复 / 活跃趋势可视化，Agent 使用分布 |
| 桌宠彩蛋 | 可拖拽桌宠（PetWidget），交互触发粒子特效 |

## 二、部署方式与环境变量说明

### 2.1 线上部署架构（已上线）

```text
浏览器 ──HTTPS──▶ Vercel（Vue3 静态站点 + /api 反代）
                        │ vercel.json rewrite: /api/(.*) → Render
                        ▼
              Render Web Service（FastAPI + Uvicorn）
                        │
        ┌───────────────┼─────────────────┐
        ▼               ▼                 ▼
   Turso 云数据库   Chroma 向量库      DeepSeek/智谱 LLM API
  （账号/会话/消息） （临时盘，可重建）   （OpenAI 兼容接口）
```

- **前端 → Vercel**：连接 GitHub 仓库 `zhangjunyong123456/zzy` 的 `main` 分支，构建命令 `npm install && npm run build`，`frontend/vercel.json` 将 `/api/*` 反向代理到 Render 后端，前端无需跨域配置。
- **后端 → Render**：新建 Web Service，根目录 `backend`，构建 `pip install -r requirements.txt`，启动 `uvicorn app.main:app --host 0.0.0.0 --port $PORT`；环境变量在 Render 控制台 Settings → Environment 配置（见下表）。
- **数据库 → Turso**：创建 libSQL 数据库，把 `TURSO_DATABASE_URL`（libsql:// 地址）与 `TURSO_AUTH_TOKEN` 配到 Render，账号/会话/消息/密钥跨重启持久化。线上推荐 `BYOK_ONLY=0` + `DAILY_FREE_QUOTA=10`（访客免 Key 可用 10 次/天）。

### 2.2 本地启动方式

```powershell
# 0. 准备：Python 3.12 venv（注意用 python.org 解释器，Anaconda 会引发 onnxruntime 崩溃）
python -m venv .venv

# 1. 配置 backend/.env（至少填一个模型 Key，推荐 DeepSeek）
DEEPSEEK_API_KEY=sk-xxxx

# 2. 预热 embedding 模型 + 灌入校园知识库（首次）
.\.venv\Scripts\python.exe scripts\warmup_models.py     # 下载 ~100MB 本地模型
.\.venv\Scripts\python.exe scripts\seed_demo.py

# 3. 启动后端（127.0.0.1:8000）
cd backend; ..\.venv\Scripts\python.exe run.py

# 4. 启动前端（http://localhost:5173，/api 自动代理到 8000）
cd frontend; npm install; npm run dev
```

## 三、核心使用流程与 AI 介入环节

### 3.1 使用流程

```text
注册/登录 ──▶ 完善个人画像 ──▶ 发起对话（一句话需求）
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        上传附件/知识库        查看多Agent并行流式回答        停止/续问
              │                   │
              ▼                   ▼
        点选对话保存记忆 ◀── 汇总行动建议（可复制/可追问）
```

1. **注册 / 登录**：用户名 + 密码（PBKDF2 哈希存储、HMAC-SHA256 签名 Token），也可游客模式先体验。
2. **完善画像**（个人中心 → 我的资料）：填年级、专业、兴趣、经历、目标。
3. **发起对话**：在主界面选一个场景入口或直接输入问题（如「我想参加蓝桥杯，帮我做备赛规划」），Enter 发送。
4. **观看多 Agent 协作**：先出现「主 Agent · 调度」卡（意图路由），随后多个专业 Agent 卡片**同时流式打字**，最后「主 Agent · 已完成」汇总成一份行动建议；随时可点红色「■ 停止」中断（已生成内容保留）。
5. **上传附件 / 维护知识库**：对话中直接传图/PDF/PPT；或到「知识库管理」上传 PDF 并标记场景（课程资料/科研论文/简历）。
6. **保存记忆**：勾选重要消息 → 保存为记忆（按类别分组），形成长期记忆库。
7. **数据统计**：个人中心查看会话数、活跃趋势、Agent 使用分布。

### 3.2 AI 介入环节说明（哪里用了 AI、怎么用）

| # | 环节 | AI 技术 | 说明 |
|---|---|---|---|
| 1 | **意图路由** | LLM 结构化输出（JSON） | 主 Agent 把用户问题分类，决定调度哪几位专业 Agent（学习/科研/竞赛/求职/校园） |
| 2 | **并行生成** | LLM 流式输出（SSE） | 被选中的 Agent 携带画像、记忆、RAG 检索结果并行作答，前端多卡片实时打字 |
| 3 | **汇总建议** | LLM 二次调用 | 主 Agent 综合各 Agent 结论，产出一份去重、按优先级排序的行动建议 |
| 4 | **附件理解** | 视觉模型 `glm-4v-flash` + 文档解析 | 图片走视觉模型识图；PDF（PyMuPDF）/PPT（python-pptx）/Word（python-docx）逐页提取后注入「【附件内容】」上下文 |
| 5 | **知识库 RAG** | `bge-small-zh-v1.5` 本地 Embedding + Chroma 向量检索 | 上传文档 → 分块 → 向量化入库；对话时语义检索 Top-K 片段注入提示词 |
| 6 | **长期记忆** | 提示词工程 | 用户点选保存的记忆按类别入库，后续对话以「【历史记忆】」注入 System 消息 |
| 7 | **画像个性化** | 提示词工程 | 画像字段拼入系统提示，让回答贴合用户背景（如大二/计算机/备战蓝桥杯） |
| 8 | **降级兜底** | 本地演示模式 | 游客或额度用尽时走 `demo` 演示流（仍展示多 Agent 调度过程，不消耗云端 LLM），保证产品始终可用 |
| 9 | **BYOK 直连** | OpenAI 兼容多供应商 | 用户自带 Key 通过 `X-LLM-Provider/Key/Model` 请求头透传，后端 `get_llm` 工厂按用户身份动态切换模型 |

## 四、技术栈清单

| 层 | 选型 | 说明 |
|---|---|---|
| **前端框架** | Vue 3 + Vite | 组合式 API、`<script setup>` |
| **UI 组件** | Element Plus | 主题经 `:root` CSS 变量统一定制 |
| **状态管理** | Pinia | 会话/消息/流式状态集中管理 |
| **图表** | ECharts（按需引入） | 活跃趋势、Agent 使用分布 |
| **流式通信** | SSE（fetch 流读取） | 带 agent 归属字段，多卡片并行打字；AbortController 支持停止生成 |
| **后端框架** | FastAPI + Uvicorn | Python 3.12；pydantic v2 校验 |
| **多 Agent 编排** | LangGraph（supervisor 模式） | 结构化输出路由 → 并行 fan-out → 汇总 |
| **LLM 接入** | langchain-openai（OpenAI 兼容） | DeepSeek / 硅基流动 / 智谱 GLM 三供应商可切换回退 |
| **向量数据库** | Chroma（嵌入式持久化） | 课程资料 / 论文 / 简历分块入库 |
| **Embedding** | fastembed + BAAI/bge-small-zh-v1.5 | 本地 ONNX 推理，无 torch 依赖 |
| **文档解析** | PyMuPDF、python-pptx、python-docx | PDF / PPT（含组合形状递归）/ Word |
| **主数据库** | SQLite（WAL） / Turso（libSQL 云库） | 自研 `turso_client`：httpx 实现 Hrana v2 pipeline，模拟 sqlite3 接口面，本地/云库无缝分流 |
| **认证安全** | PBKDF2 密码哈希 + HMAC-SHA256 签名 Token | 密钥多级回退持久化（env > 云库 app_meta > 本地文件） |
| **数据库迁移** | 幂等 `executescript` 建表 + 批量迁移脚本 | `scripts/migrate_local_to_turso.py` 本地 → 云库 |
| **测试** | pytest（80+ 用例） | 测试环境与 .env 强制解耦，防线上配置污染 |
| **部署** | Vercel（前端） + Render（后端） + Turso（云数据库） + GitHub（main/master 双分支同步） | 推送 main 自动触发 Vercel 构建部署 |

## 附：常见问题

- **注册后数据会丢吗？** 线上使用 Turso 云库持久化，服务重启数据不丢；本地未配 Turso 时数据在 `backend/data/ican.db`。
- **没配 Key 能用吗？** 能。线上默认「每日免费额度」模式（访客免 Key 可体验真 AI，用尽降级演示模式）；也可在「模型服务」页配置自己的 Key 不受限使用。
- **自带 Key 安全吗？** Key 仅保存在浏览器 localStorage，随请求头透传给后端直连模型厂商，不落库、不上传第三方。
